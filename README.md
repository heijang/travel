# Travel Map

여행 일정을 지도 위에 시각화하는 웹 앱. 다일차 여정을 Day 단위로 나눠 이동 경로를 그리고,
숙박·명소·활동을 마커로 표시한다. 마커를 누르면 상세 정보와 외부 링크가 열린다.

현재 담긴 여정: **2026-08-17 ~ 08-23, 6박 7일** — 오슬로 공항 → 트롤퉁가 → 베르겐 →
플롬/스테가스테인 → 튀인크뤼세트 → 오슬로 공항. 총 1,331km.

## 실행

```bash
npm install
```

```bash
npm run dev
```

http://localhost:5173 에서 열린다. 백엔드도 API 키도 필요 없다.

| 명령 | 설명 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm run build` | 프로덕션 빌드 (`dist/`) |
| `npm run preview` | 빌드 결과 미리보기 |
| `npm run typecheck` | 타입 검사만 |
| `npm run routes` | 경유지에서 도로 형상 생성 |
| `npm run images` | 숙소 예약 링크에서 사진 내려받기 |

화면은 두 가지다. 기본은 **일정표**, `Tour` 버튼을 누르면 **투어**로 바뀐다 (우상단).

## 투어 화면 (기본)

자동차가 7일 전체 경로를 따라 달리고, 주요 지점에 도착하면 멈춰서 그곳이 어디인지
카드로 보여준다. 정차 지점은 숙박·명소·하이킹·식사·액티비티 17곳이다. 공항·터널·주차장
같은 경유지는 들르지 않는다. 전 구간 1,128km를 1배속에서 약 2.7분에 돈다.

| 동작 | 방법 |
|---|---|
| 재생 / 일시정지 | ▶ 버튼, 또는 스페이스바 |
| 이전 · 다음 지점 | ⏮ ⏭ 버튼, 또는 ←/→ 방향키 |
| 특정 지점으로 | 하단 진행 막대의 점, 또는 지도의 번호 마커 클릭 |
| 처음부터 | ↺ |
| 배속 | `1×` 버튼 (1× → 2× → 4×) |
| 전체 경로 보기 | `전체` |

지도를 손으로 끌면 재생이 멈춘다. 카메라 따라가기와 다투지 않게 하기 위해서다.
이동수단에 따라 아이콘이 바뀌고(🚗 🥾 🚆 🚶) 줌도 함께 조정된다.

경로는 시작 전부터 Day 색으로 **연하게** 다 그려져 있고, 자동차가 지나가면 그 구간이
**진해진다**. 그래서 출발 전에도 여정 전체의 모양과 날짜 구성이 한눈에 보인다.

되짚는 구간이 있다. 트롤퉁가 하이킹이나 플롬스바나처럼 갔다가 돌아오는 곳은 실제로
돌아오는 길을 3.5배속으로 지나간다.

## 일정표 화면

| 동작 | 방법 |
|---|---|
| 일차 전환 | 상단 Day 탭, 또는 ←/→ 방향키 |
| 전체 보기 | "전체" 탭, 또는 지도 위 `전체 보기` 버튼 |
| 장소 상세 | 마커 클릭, 또는 일정 패널 항목 클릭 |
| 상세 닫기 | `Esc`, 또는 지도 빈 곳 클릭 |
| 패널 접기 | 우상단 `✕` / `☰` |

선택한 일차는 URL에 남는다 (`?day=3`). 투어 화면은 `?view=tour`다.

일정 패널은 우상단 `✕`로 닫고 `☰`로 다시 연다. 모바일에서도 동일하게 동작한다.

경로 위에는 일정 간격마다 진행 방향 화살표가 놓인다. Day 색으로 채우고 흰 테두리를 둘러
파선 구간에서도 읽힌다. 간격은 `MapView.tsx`의 `ARROW_SPACING`(기본 120px)으로 조절한다.

다크 모드는 없다. 가독성 때문에 제거했고, 라이트 한 벌만 쓴다.

```
src/

  types.ts                  Trip / Day / Place / Route / Note 타입
  lib/trip.ts               데이터 로드와 파생 계산 (bounds, 연박 이월, 메모 정렬)
  lib/tour.ts               투어 경로 생성 (구간 잇기·되짚기), 정차 지점 매핑, 속도/줌
  lib/useMapLibre.ts        지도 생성 훅 (두 화면 공용)
  components/
    TourMap.tsx             투어 화면 — 자동차 애니메이션, 진행 막대, 조작
    TourCard.tsx            도착 카드
    MapView.tsx             일정표 화면 지도 — 마커, 경로 레이어, 화살표, 팝업
    DayTabs.tsx             일차 탭
    ItineraryPanel.tsx      일정 패널
    PlaceDetail.tsx         장소 상세 (팝업과 패널이 공유)
    NoteList.tsx            메모 블록
  App.tsx                   상태 관리 (화면 모드, 선택 일차/장소, 테마, URL 동기화)
  styles.css                전체 스타일
```

기술 스택: React 19 + TypeScript + Vite, MapLibre GL JS, OpenFreeMap 무료 벡터 타일.
상태 관리 라이브러리는 쓰지 않는다.

## 데이터 수정

[`src/data/norway-fjords.json`](src/data/norway-fjords.json) 한 파일이 전부다.
스키마는 [`src/types.ts`](src/types.ts)에 있다.

### 좌표: 구글 좌표를 쓰되 순서를 뒤집는다

구글 지도는 **`위도, 경도`** 순으로 준다. 이 프로젝트는 GeoJSON/MapLibre 규약대로
**`[경도, 위도]`** 다. 순서가 반대다.

```
구글에서 복사:  60.9036, 7.1544
JSON에 넣을 값: [7.1544, 60.9036]
```

뒤집지 않으면 마커가 엉뚱한 곳(대개 바다)에 찍힌다. 노르웨이는 경도가 위도보다 확연히
작으니, **앞 숫자가 뒤 숫자보다 크면 뒤집힌 것**이다.

구글 지도에서 좌표 얻기: 지점을 우클릭하면 맨 위에 좌표가 뜬다. 누르면 복사된다.

### 장소 추가

`days[].places[]`에 항목을 넣는다. `type`은 그 장소가 **무엇인지**를 말한다.

| `type` | 뜻 | 아이콘 | 투어에서 정차? |
|---|---|---|---|
| `stay` | 숙박 | 🛏 | 예 |
| `sight` | 명소 | 📍 | 예 |
| `hike` | 하이킹 | 🥾 | 예 |
| `food` | 식사 | 🍽 | 예 |
| `activity` | 액티비티 | 🎫 | 예 |
| `transport` | 공항·역·터널·주차장 | 🚉 | **아니오** (경유지) |

투어 화면은 `transport`를 건너뛴다. 지나가기만 하는 곳을 목적지처럼 소개하지 않기
위해서다. 지도에는 그대로 표시된다.

`order`는 그날 안에서의 방문 순서이고, 연박 숙소는 체크인 날 하루치만 넣으면 된다
(`checkIn`/`checkOut`으로 이후 날짜에 자동으로 따라붙는다).

### 이동수단 설정

`type`이 "장소가 무엇인지"라면, `mode`는 "어떻게 이동하는지"다. 하루의 이동은
`days[].route`에 넣는다.

이동수단이 하나면 `route.mode` 하나로 끝난다.

```json
"route": {
  "mode": "car",
  "waypoints": [[10.7522, 59.9139], [8.2064, 60.5333], [6.5464, 60.0700]],
  "geometry": [],
  "distanceKm": 378.5,
  "durationMin": 394
}
```

하루 안에서 섞이면 `legs`로 나눈다. `legs`가 있으면 그쪽이 정답이고 `route.mode`는
그날을 대표하는 값으로만 쓰인다.

```json
"route": {
  "mode": "car",
  "legs": [
    { "mode": "car",   "from": "stay-bergen", "to": "stay-flam",
      "waypoints": [[5.3221, 60.3913], [7.1136, 60.8628]], "geometry": [] },
    { "mode": "train", "from": "stay-flam",   "to": "flamsbana",
      "waypoints": [[7.1136, 60.8628], [7.1236, 60.7317]], "geometry": [],
      "note": "플롬스바나 편도 약 1시간" }
  ]
}
```

쓸 수 있는 `mode`와 그 효과:

| `mode` | 선 모양 | 투어 아이콘 | 투어 속도 | 도로 라우팅 |
|---|---|---|---|---|
| `car` | 실선 | 🚗 | 빠름 | 예 |
| `bus` | 긴 파선 | 🚌 | 빠름 | 예 |
| `ferry` | 파선 | ⛴ | 중간 | 아니오 |
| `train` | 점선 | 🚆 | 느림 | 아니오 |
| `hike` | 굵은 점선 | 🥾 | 느림 | 아니오 |
| `walk` | 잔점선 | 🚶 | 가장 느림 | 아니오 |
| `flight` | 성긴 파선 | ✈ | 가장 빠름 | 아니오 |

### 경로선 만들기

좌표만 넣으면 **마커만 생기고 경로선은 안 생긴다.** 경로선은 `geometry`(도로 형상
좌표 수백 개)가 필요한데, 이건 손으로 못 쓴다. 대신 **`waypoints`에 거쳐 갈 지점만
찍고** 스크립트를 돌린다.

```bash
npm run routes
```

무엇이 바뀔지만 보려면:

```bash
npm run routes -- --dry
```

`car`·`bus` 구간은 OSRM 공개 서버에서 실제 도로 형상을 받아 오고, 거리·소요시간도
같이 채운다. 나머지(도보·하이킹·기차·페리)는 라우팅 서버가 지원하지 않으므로
`waypoints`를 그대로 선으로 잇는다. **그런 구간은 waypoints를 촘촘히 찍을수록 실제
경로에 가까워진다.**

`geometry`는 스크립트의 출력이므로 직접 고치지 않는다. 경로를 바꾸려면 `waypoints`를
고치고 다시 돌린다.

노르웨이에서 이 단계를 건너뛰면 안 되는 이유: 피오르 때문에 직선과 실제 도로가 크게
어긋난다. 오슬로→오다는 직선 120km인데 실제 도로는 378km다.

메모는 `Place.notes`와 `Day.notes`에 배열로 넣는다.

```json
"notes": [
  { "kind": "warning", "text": "9월 중순 이후엔 가이드 동반 필수." },
  { "kind": "tip", "text": "새벽 5시 출발하면 대기가 없다." }
]
```

시각이 중요한 지점에는 `time`을 넣는다 (`"11:30"`). 넣은 지점만 일정 패널·투어 카드에
표시된다. 체류 시간은 별개로 `durationMin`이다.

`kind`는 `warning`(주황 ⚠) / `tip`(파랑 💡) / `note`(회색 📝) 셋 중 하나다. 메모가 있는
마커에는 배지가 붙고, 여러 개면 가장 강한 것 하나만 노출한다 (warning > tip > note).
줄바꿈(`\n`)은 그대로 표시된다. 메모는 플레인 텍스트로만 렌더링하며 HTML/마크다운을
해석하지 않는다.

연박 숙소는 체크인 날 하루치만 넣으면 된다. 패널이 `checkIn <= 날짜 < checkOut` 조건으로
이후 일차에도 "연박"으로 끌어온다.

## 데이터의 미확정 부분

`_meta.warnings`에도 같은 내용이 있다. 이 시드 데이터는 **그대로 여행 계획에 쓰면 안 된다.**

1. **숙소 4곳은 실존 업체가 아니다.** 좌표는 마을 중심, 요금은 예상치다.
2. **링크 URL과 메모의 사실관계는 검증 전이다.** 트롤퉁가 개방 시기, 플롬스바나 소요시간,
   레르달 터널 좌표 등은 공식 사이트에서 확인해야 한다.
3. **하이킹·산악철도 구간 좌표는 손으로 찍은 근사치다.** 라우팅 API로 나오지 않는다.
   도로 구간은 OSRM에서 뽑은 실제 형상이다.

## 사진

```bash
npm run images
```

각 지점의 사진을 `public/photos/<id>.jpg`로 내려받고 `imageUrl`을 채운다.
`--dry`는 확인만, `--force`는 이미 받은 것도 다시 받는다.
사진은 지도 마커(숙소는 원형), 투어 카드, 상세 팝업 세 곳에 나온다.

출처는 두 가지다.

| 대상 | 출처 | 저작자 표시 |
|---|---|---|
| 숙소 | 예약 링크의 Open Graph 미리보기 이미지 | 없음 (본인 예약 건) |
| 그 외 | `wikipedia` 필드의 문서 대표 이미지 (Wikimedia Commons) | **필수** |

Commons 이미지는 대부분 CC BY / CC BY-SA다. 스크립트가 저작자와 라이선스를 함께 받아
`imageCredit`에 넣고, 화면에서는 사진 아래 작은 글씨로 표시된다. **저작자나 라이선스를
받지 못하면 그 사진은 아예 쓰지 않는다** — 출처 없이 싣지 않기 위해서다.

새 지점에 사진을 붙이려면 그 장소에 `"wikipedia": "<영문 문서 제목>"`을 넣고 다시 실행한다.

CDN을 직접 링크하지 않고 내려받는다. 예약 사이트의 이미지 URL은 호스트가 숙소를 편집하면
바뀌고, 어느 쪽도 교차 출처 제공을 계속한다는 보장이 없다. 로컬 사본이라야 항상 보인다.
대신 오래되니 갱신하려면 다시 실행한다.

Wikimedia API는 짧게 몰아 호출하면 429를 돌려준다. 스크립트가 `Retry-After`를 읽어
기다렸다 재시도하므로 그냥 두면 된다.

**마커 사진을 건드릴 때 주의**: 문서에 붙지 않은 `<img>`에 `loading="lazy"`를 주면
영원히 로드되지 않는다. 지연 로딩이 뷰포트 진입을 기다리는데 분리된 요소는 들어갈 일이
없기 때문이다. 먼저 붙이고 실패하면 되돌리는 순서를 유지한다.

## 지도 코드를 고칠 때

`useMapLibre` 훅에 지도 생성 순서가 몰려 있다. 화면마다 지도를 직접 만들지 말고 이 훅을
쓴다. 컨테이너 크기가 잡히기를 기다리는 것, StrictMode 이중 마운트를 피하는 것,
`load`가 아니라 `style.load`를 준비 신호로 쓰는 것 — 셋 다 이유가 있고 주석에 적어뒀다.

**`line-gradient`에 넘기는 진행률은 `TourPoint.frac`을 쓴다.** MapLibre의
`line-progress`는 메르카토르 투영 거리로 재기 때문에, 지상 거리(km) 비율을 넘기면 색
경계가 자동차와 어긋난다. 이 여정에서는 최대 2.4km 벌어졌고 베르겐 도보 구간(1.2km)에서
증상이 드러났다. 진행 막대는 반대로 지상 거리를 써야 맞다.

**마커 요소에 `transform`이나 `transition: transform`을 걸지 않는다.** MapLibre가 그
속성으로 마커 위치를 잡기 때문에, 건드리면 마커가 지도를 따라 헤엄치거나 제자리를 벗어난다.
확대·색 전환 같은 효과는 `.marker__inner`, `.tourstop__inner` 같은 안쪽 래퍼에 건다.
이 프로젝트에서 두 번 밟은 함정이다.
